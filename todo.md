- [ ] **1. Knowledge Item frame and first Kinds.** New `src/subdomains/knowledge` (database, `knowledge` sub-API of `WorkspaceApi`, gateway controller); `CleanupAdapter` calls its removal for a Project and a Workspace, so Knowledge Items go with them; `afterMemberRemoved` leaves them in place, Drafts included. Knowledge Item with the common frame: Kind, Knowledge Key, title, status (Draft only for now), Source with Rationale (by hand for now; the Source never changes, the Rationale is edited with the Draft), author (the Member who recorded it, never changes) and who edited it last and when (no history beyond that). Kinds Term, Requirement, Decision with their fields; only each Kind's main field is required (`docs/notes/knowledge-kinds.md`). REST: record a Draft, edit a Draft, delete a Draft (Deletion: a mistake, not a Rejection), get one, list a Project's knowledge (Drafts marked, Rejected left out). Rights through a Knowledge policy on top of Tenancy's `AccessResolver` and `AccessPolicyService`, one check given the Member, the Project and the Kind: Contributor and Maintainer record, edit and delete Drafts, Viewer only reads, an outsider gets 404.
  - Decided: Knowledge Keys numbered per Kind within a Project, from a counter document per (Project, Kind prefix) bumped with `$inc` in the recording transaction.
  - Decided: each Kind's fields are a value object in the domain (`TermContent`, `RequirementContent`, `DecisionContent`); contracts have one zod schema per Kind, joined on `kind`; application maps one to the other. Revisit before step 4 if it proves heavy.
  - Decided: REST under `/api/workspaces/:workspaceId/projects/:projectId/knowledge`, an item addressed by its Knowledge Key (`…/knowledge/REQ-12`): `POST` records a Draft, `GET` lists (`?kind=…&status=…&take=…&offset=…`, `take` 50 by default and at most 200; answers `{ items, total }`, sorted by Kind, then by the Knowledge Key's number), `GET /:key` reads one, `PATCH /:key` edits a Draft, `DELETE /:key` deletes a Draft. A Draft's Kind never changes: one recorded under the wrong Kind is deleted and recorded again. Body `{ kind, title, rationale?, fields }`.
