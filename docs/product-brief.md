# Intentra - Product Brief

## Что такое Intentra

**Intentra** - AI-платформа для формирования, структурирования и постоянного поддержания контекста программного проекта.

Система помогает превратить знания, идеи и решения, которые обычно разбросаны по чатам, головам участников и документации, в структурированную и актуальную модель проекта, пригодную как для людей, так и для AI-агентов.

Основная идея:

> **Поговорить с Intentra о продукте -> получить структурированный контекст проекта -> использовать этот контекст для проектирования и разработки людьми и AI-агентами.**

---

## Проблема

При разработке ПО значительная часть контекста существует в неструктурированном виде:

- бизнес-идея и цели продукта;
- функциональные требования;
- нефункциональные требования;
- бизнес-правила;
- ограничения;
- терминология предметной области;
- архитектурные решения;
- инфраструктурные требования;
- договорённости команды;
- причины принятых решений.

Со временем этот контекст устаревает, теряется или оказывается распределён между людьми, таск-трекерами, чатами и документацией.

AI-агенты также не владеют полной картиной проекта и вынуждены каждый раз восстанавливать контекст перед выполнением задачи.

---

## Цель продукта

Создать **единый источник актуального контекста проекта**, который:

1. формируется совместно с AI через диалог;
2. автоматически превращается в структурированную документацию;
3. развивается вместе с проектом;
4. используется для создания требований, Specs и ADR;
5. доступен внешним AI-агентам через **MCP**.

---

## Основной пользовательский flow

### 1. Workspace

Компания или отдельный пользователь регистрируется в Intentra и создаёт **Workspace**.

Workspace объединяет пользователей и проекты организации.

### 2. Project

Внутри Workspace пользователь создаёт **Project**.

Project становится контейнером всего контекста конкретного программного продукта.

### 3. AI Interview

Пользователь начинает диалог с AI.

AI последовательно исследует проект, задаёт уточняющие вопросы и помогает сформулировать недостающую информацию.

Например:

- Что за продукт создаётся?
- Какую проблему он решает?
- Кто его пользователи?
- Какие существуют роли?
- Какие основные пользовательские сценарии?
- Какие бизнес-правила?
- Какие ограничения?
- Какие интеграции необходимы?
- Какие требования к безопасности?
- Какие требования к производительности?
- Какая предполагается архитектура?
- Как будет устроена инфраструктура?

AI должен не просто вести чат, а **постепенно строить формальную модель проекта**.

## Project Knowledge

На основании диалогов Intentra формирует и постоянно обновляет структурированную базу знаний проекта.

Она может включать:

### Product Context

- описание продукта;
- проблема;
- цели;
- целевая аудитория;
- основные сценарии использования;
- ограничения;
- stakeholders.

### Domain Context

- ubiquitous language;
- основные сущности и понятия;
- бизнес-правила;
- связи между понятиями;
- bounded contexts / domains.

### Functional Requirements

- возможности системы;
- пользовательские сценарии;
- use cases;
- роли и права;
- правила поведения системы.

### Non-Functional Requirements

- производительность;
- масштабирование;
- безопасность;
- доступность;
- отказоустойчивость;
- аудит;
- observability;
- инфраструктура;
- deployment;
- compliance и другие технические ограничения.

---

## Документация

Intentra использует накопленный Project Knowledge для создания и поддержки инженерной документации.

В дальнейшем система должна уметь формировать:

- Product documentation;
- Requirements;
- Specifications;
- ADR;
- Domain documentation;
- Architecture documentation;
- API / Integration specifications;
- другие документы, необходимые для разработки.

Документы являются не отдельными статичными файлами, а **представлениями единого контекста проекта** и могут обновляться при изменении требований или решений.

## AI как аналитик проекта

AI в Intentra выступает прежде всего как:

- Product Analyst;
- Business Analyst;
- System Analyst;
- Requirements Engineer;
- Architecture Assistant.

Его задача - не просто отвечать пользователю, а:

- находить пробелы в требованиях;
- выявлять противоречия;
- задавать уточняющие вопросы;
- предлагать варианты решений;
- фиксировать принятые решения;
- связывать решения с требованиями;
- поддерживать документацию в актуальном состоянии.

При этом ключевые продуктовые и архитектурные решения остаются за человеком.

---

## MCP

Intentra предоставляет **MCP Server**, через который внешние AI-агенты получают доступ к контексту проекта.

Например пользователь может подключить:

- Codex;
- Claude Code;
- Cursor;
- собственных AI-агентов.

Агент сможет запросить:

- описание продукта;
- терминологию;
- требования;
- бизнес-правила;
- архитектурные ограничения;
- ADR;
- Specs;
- контекст конкретной задачи или части системы.

Таким образом AI-разработчик получает не просто repository context, а **product + domain + requirements + architecture context**.

---

## Конечный vision

Intentra должна стать **knowledge and intent layer между человеком и AI-разработчиком**.

```text
Human / Team
      ↓
   Intentra
      ↓
Product Intent
Requirements
Domain Model
Architecture
Decisions
Specifications
      ↓
     MCP
      ↓
Codex / Claude / AI Agents
      ↓
   Software
```

То есть Intentra отвечает за вопрос:

> **«Что мы строим, зачем мы это строим, как это должно работать и какие решения уже были приняты?»**

А coding-агенты используют этот контекст, чтобы отвечать на следующий вопрос:

> **«Как это реализовать в коде?»**
