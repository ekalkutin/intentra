# Синхронные вызовы между контекстами разрешены

Дата: 2026-09-22. Статус: принято.

## Контекст

Контексты не импортируют друг друга — это держит линтер. Оставался вопрос, как они
общаются. В родственном проекте того же автора (x-lance) синхронные вызовы между
контекстами запрещены полностью: контексты зовёт только шлюз, между собой они
обмениваются событиями, и даже «обеспечь учётную запись для этой почты» сделано двумя
событиями. Единственное исключение там — один названный контекст ниже по течению.

## Решение

Контекст может синхронно звать опубликованный API соседа через клиентский порт, когда
ему действительно нужен ответ. Факт состоявшегося изменения публикуется событием.
Шлюз оркестрирует последовательность шагов и не содержит правил.

Доставка событий в MVP — внутрипроцессная, но форма контракта та же, что под брокер
(`libs/contracts/<контекст>/events`): появление брокера меняет доставку и ничего больше.

## Considered Options

- **Полный запрет, как в x-lance.** Отвергнуто осознанно: «существует ли аккаунт с
  такой почтой» через два события — заметно более сложный код ради границы, которую в
  монолите пока никто не проверяет на прочность.
- **Запрет с одним исключением для контекста ниже по течению** (`agent-runtime`).
  Отвергнуто по той же причине, но остаётся ближайшим запасным вариантом.

## Consequences

- Между контекстами образуется граф синхронных вызовов, который никто не держит в
  голове. Это принятый риск: признак того, что решение пора пересматривать, — первый
  цикл в этом графе или первый вызов, который приходится ждать дольше, чем можно.
- Локальный кеш ответов соседа — сознательно вне объёма MVP.
