# Профиль агента принадлежит одной области, видимость идёт сверху вниз

Дата: 2026-09-22. Статус: принято.

## Контекст

Агенты нужны на разных уровнях: Discovery, Architect и Spec Writer — общие для всей
платформы; агент, знающий стек команды, осмыслен в пределах одной продуктовой линии;
путеводитель по PRD конкретного проекта бессмысленен где-либо ещё. Обсуждались два
способа выразить это: список областей у профиля (`workspaces[]`, `projects[]`) и
единственная область владения.

## Решение

`AgentProfile` принадлежит ровно одной области: платформа, workspace или проект.
В проекте доступны профили самого проекта, его workspace и платформенные — то же
направление, что у прав: сверху вниз, только добавляет.

Профиль хранит только конфигурацию. Контекст, переписка, память, инструменты и
учётные данные принадлежат запуску и приходят от проекта, в котором он идёт. Поэтому
общий профиль, запущенный в двух проектах, не переносит знание одного в другой.

## Considered Options

- **Списки областей.** Отвергнуто: список отвечает на вопрос «где доступен» и не
  отвечает на вопрос «кто владеет и кто вправе править», так что владельца пришлось бы
  добавлять отдельно. Кроме того, список надо поддерживать руками, и он тихо устаревает
  при удалении проектов.
- **Владелец плюс список публикации.** Отвергнуто по объёму: случая «нужен в A и C,
  но не в B» в MVP нет ни одного. Когда появится, список публикации добавляется
  поверх принятого решения, ничего не ломая.

## Consequences

- Системные шаблоны — данные уровня платформы, только для чтения; правит их
  `PlatformAdmin`, и правка действует на всех немедленно. Поэтому `AgentVersion`
  обязателен сразу: запуск ссылается на версию, иначе вчерашний результат задним
  числом меняет смысл.
- Кнопка «сделать свой на основе шаблона» создаёт отдельный профиль и рвёт связь с
  оригиналом: улучшения платформы до копии не доезжают.
