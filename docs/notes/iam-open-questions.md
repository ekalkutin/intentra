# IAM — open questions and deferred ideas

## Deferred (post-MVP)

- **Revocable refresh tokens.** MVP: access and refresh tokens are stateless JWTs returned in the response body; the access token travels as `Authorization: Bearer`. A refresh token cannot be revoked and stays valid until it expires, and logout only means the client forgets its tokens. Later: store refresh sessions in Redis with a TTL, delete the key on logout, keep an Account's session keys in one set for "log out everywhere", and rotate the refresh token on every refresh.
- **Email verification.** See [workspace open questions](workspace-open-questions.md): an Invitation relies on the email being owned by the Account.
- **Access for MCP agents.** Decided on 2026-09-29: a Personal Access Token belongs to a Member and lives in the Workspace context, not in IAM (like Linear or Slack, unlike Atlassian's account-wide tokens). OAuth for MCP is built on top of the same model (decided on 2026-10-03): approving a client on the consent page creates a Personal Access Token and hands it to the client as its access token, with no refresh token; the gateway acts as the authorization server, with open Dynamic Client Registration and PKCE.
- **Deleting an Account.** Decided on 2026-10-01: for now a Platform Admin can only block and unblock an Account (Blocked Account). Deleting one, by a Platform Admin or on the person's own request, needs its own grilling: what happens to its Members, the Knowledge Items it authored, its Conversations, and a Workspace where it is the last Owner.
- **A blocked Account's open session.** Decided on 2026-10-01: blocking refuses sign-in and refresh at once and revokes its Members' Personal Access Tokens, but an access token already issued keeps working until it expires (at most `IAM_ACCESS_TOKEN_TTL_SECONDS`, 15 minutes), as the Platform Admin mark does. If that ever matters, check the Account on every request or keep a deny list of tokens.
- **Telling Workspace that an Account was blocked.** Decided on 2026-10-01: there is no event bus, so the gateway calls IAM (block the Account) and then Workspace (revoke the Personal Access Tokens of that Account's Members), in two transactions. Both are idempotent: if the second fails, blocking again finishes the job. Move it to events once the contexts have them.
