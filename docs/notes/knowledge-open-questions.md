# Project Knowledge: open questions

Deferred on purpose. Glossary: `packages/workspace/src/subdomains/knowledge/CONTEXT.md`.

- **Approving by Kind.** Decided on 2026-09-29: a Project's Maintainers approve, reject, supersede and retire every Kind. Later, if teams need "only certain people approve Decisions", add owners per Kind on top of Project Roles (like GitHub CODEOWNERS), not job-title roles. What to lay down now: every approve / reject / supersede / retire goes through one permission check given the Member, the Project and the Kind; every Knowledge Item records who approved, rejected, superseded or retired it and when.
- **Approving over MCP.** An external agent may approve, reject, supersede or retire on a Member's behalf only when the Member's personal access token allows it; that permission is off by default. Decided on 2026-09-29: the Personal Access Token (Workspace context) has three levels, and only the highest lets the agent approve. Intentra's own Agents have no tool to approve at all.
- **Links to external artifacts.** A Source from an external agent could also point to a commit, pull request or file it came from. Comes with Planning (Commit / PR / Test evidence).
- **Activity log.** Decided on 2026-09-30: a Knowledge Item keeps one named field pair per lifecycle transition (each happens at most once), not a list of events. A feed of what happened in a Project (edits, approvals, Needs Review confirmations, which can repeat) would be its own append-only collection written from domain events, not an array inside each Knowledge Item.
- **Marking a Term's users when its meaning changes.** Decided on 2026-09-30: `uses term` does not set Needs Review (too noisy). If a Term's meaning really changes ("Customer" now includes companies), a later option on its Supersession could mark every item that uses it, on the approver's explicit choice.
- **Context for a task: finding the anchors.** Decided on 2026-10-02: an agent builds the context for its task from anchors it picks itself, by Knowledge Key, out of the compact list (`list_knowledge`, `get_knowledge_summary`); Intentra walks the Links from them, deterministically, with no embeddings and no model call of its own. We will grow it in two ways, both feeding the same walk:
  - *By the task's text:* the agent passes "add revoking an Invitation" and Intentra finds the anchors itself (semantic search over embeddings, or an Intentra agent on the Workspace's Provider Key). Add it once agents are seen picking the wrong anchors or too few.
  - *By Feature:* a new Kind, Feature ("Invitations to a Workspace"), linked to its Scenarios, Requirements and Business Rules, becomes the natural anchor (`FEAT-3`), and Planning grows from it (Feature → Task).
- **Project frame: marking what applies to the whole Project.** Decided on 2026-10-02: the project frame an agent reads once per session (`get_project_frame`) holds the Product Overview, every Approved Constraint and every Approved non-functional Requirement; nothing is marked. Once frames in live Projects pass about 20–30 items, add a `scope` to Constraint and Requirement, `project` by default, `local` allowed only on an item with at least one Link (otherwise it would reach no frame and no context at all); a `local` item leaves the frame and reaches agents only through the Links walk. The Orchestrator sets `local` itself when it is obvious and never asks. Changing it on an Approved item takes a Supersession, like any other field.
- **Context Pack from several Anchors in the UI.** Decided on 2026-10-02: the web UI shows the Context Pack of one Anchor, from its Knowledge Item's page; MCP takes several. Picking several Knowledge Items in the list (checkboxes) to see and copy their Context Pack comes later, if people ask for it.
- **Linking `uses term` automatically.** Decided on 2026-10-02: Links come from the Orchestrator (with concrete rules in its instructions) and from people; an Approved Knowledge Item with no Link either way is shown as unlinked, to people and to agents in `get_knowledge_summary`, since its Context Pack would hold only itself. Later, perhaps: Intentra finds a Term's word in a Knowledge Item's text and suggests the `uses term` Link. Needs morphology for Russian ("приглашения", "приглашением") and must stay a suggestion a person approves, never a Link added by itself.
